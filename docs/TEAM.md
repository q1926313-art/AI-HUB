# AI 팀 사용 안내

AI Hub의 **AI 팀**은 하나의 목표를 계획·구현·검토·검증으로 나누어 각 역할의 AI를
순서대로 실행하는 기능입니다. 앞 역할의 보고서와 원래 목표를 다음 역할에 전달합니다.
이 문서는 `0.1.24`의 동작을 설명합니다.

## 시작하기

1. 사용할 CLI를 PC에 설치하고 각 도구의 로그인을 마칩니다.
   기본 구성에는 Claude Code, Codex, OpenCode가 사용됩니다. OpenCode에서는 Go 공급자를 연결합니다.
2. AI Hub의 사이드바 하단 **AI 팀**을 누르면 전용 **AI 팀 Space → 팀 관리** 탭으로 이동합니다.
   다시 눌러도 같은 Space를 사용합니다. 명령 팔레트의 **AI 팀**이나
   `herdr-app do mod.open --name team`으로도 열 수 있습니다.
3. **역할 설정**에서 담당 도구의 설치 상태와 사용할 모델·추론 강도를 확인합니다.
   설치된 다른 도구를 선택하거나 필요 없는 역할을 끄고, 프로젝트에 맞는 지침을 저장할 수 있습니다.
4. **새 작업**에서 작업 이름, 목표와 완료 조건, 프로젝트 폴더의 전체 경로를 입력합니다.
5. **AI 팀 시작**을 누릅니다. **시작하면 실시간 작업 탭으로 이동**이 켜져 있으면 같은 Space의
   작업 탭에서 실제 팀 터미널을 보여줍니다. 로그인·신뢰·권한 질문은 이 화면이나 해당 역할의
   **작업 탭에서 보기**에서 확인하고 처리합니다.
6. 보고서가 도착하면 변경사항, 검사 결과, 남은 문제를 읽고
   **인수인계 확인 · 다음 단계 실행**을 누릅니다. 마지막 역할에서는 팀 작업을 마칩니다.

### 프로젝트 폴더와 Claude의 신뢰 확인

프로젝트 폴더에는 작업할 코드가 있는 폴더를 지정하세요. 예를 들어 `C:\projects\my-app`입니다.
전용 팀 관리 화면에서 새 작업의 폴더를 처음 채울 때는 선택된 기존 작업의 프로젝트를 우선합니다.
홈 폴더가 기본값으로 잡히는 경우에는 입력을 비워 프로젝트를 직접 선택하도록 합니다.
사용자가 직접 입력하거나 선택한 경로를 화면 전환 때문에 덮어쓰지 않습니다.

Claude가 `Accessing workspace: C:\Users\...`와 함께 홈 폴더라는 안내를 표시하면,
그 폴더의 신뢰 승인은 현재 세션에만 적용됩니다. 따라서 같은 홈 폴더에서 다음 Claude를
시작하면 다시 질문할 수 있습니다. 프로젝트 폴더에서 처음 표시되는 신뢰 질문은 경로와
프로젝트를 확인한 뒤 직접 처리하세요.
([Claude Code 공식 안내](https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust))

Windows에서는 PowerShell 시작 설정을 읽은 뒤 선택된 프로젝트로 이동하고 AI나 모델 조회를
시작합니다. 해당 폴더로 이동할 수 없으면 다른 위치에서 실행을 이어가지 않고 실패를 알립니다.
기존 작업의 폴더와 이미 실행된 터미널의 위치는 업데이트만으로 바뀌지 않습니다.
기존 작업에 잘못된 폴더가 저장됐다면 **현재 AI 중지 요청** 후 터미널 상태를 확인하고,
올바른 프로젝트 폴더로 새 작업을 만드세요.

### 기본 역할

| 순서 | 역할 | 담당 도구 | 기본 요청 |
|---|---|---|---|
| 1 | 계획 | Claude Code | 기존 규칙과 코드를 읽고 범위, 구현 순서, 확인 기준 정리 |
| 2 | 구현 | OpenCode Go · DeepSeek V4.1 Flash | 요청 범위의 코드 구현, 기존 변경 보존, 필요한 검사 실행 |
| 3 | 검토 | Codex | 변경 내용, 누락, 회귀 가능성을 읽기 전용으로 검토 |
| 4 | 검증 | Claude Code | 허용된 검사를 실행하고 직접 확인한 결과와 미실행 검사 구분 |

담당 도구를 같은 것으로 통일해도 각 역할은 별도 터미널에서 시작합니다.
설정 변경은 **새로 만드는 작업**에 적용됩니다. 진행 중인 작업에는 시작 당시 역할과 지침이 남습니다.

### 역할과 담당 바꾸기

**AI 팀 → 역할 설정**에서 다음 항목을 편집하고 **역할 저장**을 누릅니다.

| 항목 | 바꿀 수 있는 내용 |
|---|---|
| 역할 이름 | 계획·구현 등의 이름을 원하는 이름으로 변경 |
| 역할 순서 | 위·아래 이동으로 실행 순서 변경 |
| 역할 추가·삭제 | 1~8개로 구성; 실제 사용할 역할은 최소 1개 필요 |
| 담당 도구 | 설치된 Claude Code·Codex·OpenCode 등 선택 |
| 담당 모델 | Claude Code·Codex·OpenCode의 모델 목록 선택 또는 정확한 ID 직접 입력 |
| 추론 강도 | 해당 도구와 선택한 모델에서 확인된 지원값 선택; 기본값은 CLI 설정 유지 |
| 작업 방식 | 자문·검토 또는 구현·수정 지침 선택 |
| 역할 지침 | 해당 AI가 해야 할 일과 확인할 사항 작성 |

모델 입력을 비우면 해당 도구에 설정된 기본 모델을 사용합니다. 도구를 바꾸면 이전 도구의 모델은
비워지고 새 도구의 모델을 선택할 수 있습니다. 모델을 직접 지정하는 기능은 Claude Code·Codex·OpenCode에서
지원하며, 다른 도구는 그 도구의 기본 모델을 사용합니다.

Claude·Codex에는 공식 문서에서 확인한 모델 선택지를 제공하고, 설치된 도구의 모델 목록이
있는 경우 그 정보를 사용합니다. 모델 목록이 계정의 실제 호출 권한을 보장하지는 않습니다.
추론 강도는 모델마다 지원값이 다릅니다. 지원 정보를 확인하지 못한 모델은 임의의 강도를
강제하지 않고 도구 기본값을 사용하도록 안내합니다. 선택한 강도가 지원되지 않으면 알리고,
더 낮은 값이나 다른 모델로 조용히 바꾸지 않습니다.
진행 화면의 모델·추론 강도는 **실행에 요청한 설정**입니다. 별칭이 실제 어떤 모델로 연결됐는지는
해당 CLI가 표시하는 모델 이름으로 확인하세요.

역할을 이동하거나 추가·삭제해도 다른 역할에서 편집하던 이름·모델·지침은 유지됩니다.
저장하지 않은 역할 설정이 있으면 다른 화면으로 이동하거나 닫기 전에 저장하거나 **변경 취소**를 누릅니다.
이전 버전의 기본 설정을 그대로 사용한 경우에는 새 기본 조합으로 바뀝니다. 직접 편집한 설정과
이미 만든 작업 기록은 보존되며, 새 기본값을 원하면 **기본 역할 불러오기 → 역할 저장**을 사용하세요.

### OpenCode Go의 DeepSeek 4.1 1017

기본 구현 역할에는 다음 전체 ID를 지정합니다.

```text
opencode-go/deepseek-v4.1-flash
```

2026-11-24에 확인한 [공식 Go 모델 목록](https://models.opencode.ai/providers/opencode-go/)은
표시 이름 **DeepSeek V4.1 Flash 1017**, Go API 모델 이름 `deepseek-v4.1-flash`, 공급자
`opencode-go`를 구분합니다. 전체 선택값에 `-1017`을 임의로 덧붙이지 마세요.
이 API 이름은 제공자의 별칭이므로 향후에도 1017 버전을 고정한다는 의미는 아닙니다.

역할 설정의 **모델 목록 불러오기**로 설치된 OpenCode의 목록을 가져오고 `deepseek` 또는
`opencode-go/`로 검색해 선택할 수 있습니다. 조회는 선택한 프로젝트 폴더에서 `opencode models`를
실행하며 AI에게 작업을 요청하지 않습니다. 목록에 보인다는 사실만으로 계정의 호출 권한까지 확인된 것은 아닙니다.

실행할 때 선택한 전체 ID가 목록에 없으면 오류를 표시하고 시작을 멈춥니다. Go 모델을 찾지 못했다고
다른 공급자의 모델로 바꾸거나 지정한 모델을 생략하지 않습니다. CLI의 `--help`로 지원 옵션을 확인하고,
모델과 시작 지시문을 지원하는 대화형 시작 방식을 사용합니다. 실행 설정에서 `opencode run`을 직접
선택한 경우에는 그 실행 방식을 유지합니다.

AI 팀의 OpenCode 실행 설정에는 `opencode` 또는 해당 실행 파일의 경로를 직접 지정합니다.
`mini`·`run`을 지정한다면 실행 파일 바로 뒤에 둡니다. `npx` 등의 래퍼 명령과 별도의 프로젝트 위치 인자는
이 기능에서 지원하지 않습니다. 프로젝트는 AI 팀에서 선택하세요.

CLI 옵션 근거: [공식 OpenCode 명령 안내](https://opencode.ai/docs/cli/commands/).

자문·검토의 읽기 전용 지침은 AI에게 주는 요청입니다. 운영체제의 파일 쓰기 권한을
제한하는 기능은 아닙니다. AI Hub는 도구의 기존 실행 인자를 유지하고 권한 확인을 일괄 생략하는
옵션을 추가하지 않습니다. 각 CLI가 지원하는 권한 설정은 해당 도구에서 관리하세요.

## AI 팀 Space와 실시간 작업 탭

AI 팀은 일반 Space 하나에 **팀 관리**와 **실시간 작업** 탭을 둡니다. 팀 관리에서
새 작업·진행 상황·역할 설정·작업 기록을 보고, **실시간 작업 탭 열기**로 실제 터미널을 함께 봅니다.
새 작업에서 자동 이동을 켜 두면 첫 역할을 시작한 뒤 작업 탭을 엽니다. 시작을 기다리는 동안
다른 Space로 이동했다면 작업 탭을 준비해도 현재 보고 있는 Space를 빼앗지 않습니다.

| 위치 | 기본 담당 | 동작 |
|---|---|---|
| 왼쪽 65% | Claude Code | 계획을 보여주고, 검증 역할이 시작되면 그 실행으로 연결 |
| 오른쪽 위 | Codex | 차례가 오기 전에는 대기, 시작하면 실제 검토 터미널 표시 |
| 오른쪽 아래 | OpenCode | 차례가 오기 전에는 대기, 시작하면 실제 구현 터미널 표시 |

상단에서 왼쪽 너비를 55/65/75%로 고릅니다. 각 칸의 **담당** 메뉴로 특정 도구의 현재 역할을
따라가거나 한 역할을 고정할 수 있습니다. 선택 목록은 같은 탭 안에서 펼쳐집니다.
같은 터미널을 두 칸에 중복 연결하지 않습니다.
출력, 명령 실행과 승인 요청은 실제 CLI 화면이며 키보드·마우스로 조작할 수 있습니다.
모델이 출력하지 않는 비공개 사고 과정을 새로 만들어 보여주는 기능은 아닙니다.

이 화면은 기존 팀 실행을 관찰합니다. 새 AI 세션을 추가 실행하거나 역할을 병렬로 시작하지 않습니다.
터미널이 추가되는 동안 배치가 바뀌면 같은 탭의 최신 내용을 다시 읽어 표시합니다.
화면을 복구하기 위해 현재 AI를 다시 시작하거나 새 작업을 만들 필요는 없습니다.
앞 역할의 보고서를 확인할 때는 **팀 관리 · 보고서**로 관리 탭에 돌아갑니다. 다른 탭·Space로
이동하거나 역할 설정·작업 기록 화면을 보는 동안에도 관리 탭이 실행 상태와 자동 진행 조건을 확인합니다.
다른 작업 기록을 선택하거나 새 작업을 실제 시작하면 이전 작업의 자동 진행은 해제됩니다.

한 터미널이 종료되면 그 칸은 보고서나 대기 안내로 바뀌고 나머지 화면과 Space는 유지됩니다.
이전 역할과 재시도의 살아 있는 터미널은 같은 작업 탭의 숨겨진 보관 영역에 유지합니다.
**담당**에서 특정 역할을 고르면 다시 볼 수 있습니다. 이전 버전의 팀 터미널을 가져올 때에는
작업·역할·시도 식별 정보가 일치하는 실행만 이동합니다.

일반 탭·Space의 닫기 동작을 사용하므로 **작업 탭을 닫으면 그 안의 터미널도 종료됩니다.**
AI 팀 Space를 닫으면 그 안의 터미널을 종료하고 이후 역할의 자동 진행을 멈춥니다.
앱 자체를 정상 종료하는 것은 기존 앱의 터미널 유지 정책을 따릅니다. 다시 열면 화면과 기록을
복원해도 자동 실행은 켜지지 않습니다. 닫은 작업 탭은 명시적으로 다시 열기 전까지 재생성하지 않습니다.

## 인수인계와 자동 진행

기본값은 **수동 인수인계**입니다. 보고서에는 작업 요약, 변경사항, 테스트 명령과 결과,
남은 문제, 다음 역할에 전달할 내용이 포함됩니다. 화면의 **통과 보고**는 AI가 제출한 결과이며,
AI Hub가 그 명령을 별도로 재실행해 확인했다는 뜻은 아닙니다.

자동 진행을 선택하면 다음 조건을 확인합니다.

- 현재 작업·역할·시도 번호와 일치하는 유효한 완료 보고서가 있습니다.
- 실행 엔진에서 작업 진행 또는 완료된 응답 기록을 확인한 뒤 대기·완료 상태가 되었거나,
  프로세스가 종료 코드 0으로 끝났습니다. 시작 직후의 대기 상태만으로는 진행하지 않습니다.
- 보고서에 실패한 검사나 남은 문제가 없습니다. `not_run`은 실행하지 않은 검사로 표시되며,
  그 자체를 실패로 처리하지는 않습니다.

로그인·권한 확인 등 입력 대기, 오류, 실행 중단, 실패한 검사나 남은 문제를 확인하면 자동 진행을
멈춥니다. 보고서가 없거나 쓰는 중이어서 유효하지 않으면 다음 역할을 시작하지 않습니다.
보고서가 있어도 실행 중인 AI를 건너뛰어 다음 역할을 실행하지 않습니다.
보고서 파일을 먼저 작성하고 마지막 응답을 마무리하는 동안에는 자동 진행을 유지한 채 기다립니다.

**자동 진행 멈추기**는 이후 역할의 자동 실행을 멈추며 현재 AI의 작업은 계속됩니다.
현재 작업까지 멈추려면 **현재 AI 중지 요청**을 사용하고 터미널 상태를 확인하세요.
관리 탭을 닫거나 다른 작업 기록을 선택하거나 보고서를 편집하면 자동 진행은 해제됩니다.
단순한 탭·Space 전환과 역할 설정 화면 이동은 자동 진행을 유지합니다.
앱이나 기록을 다시 열었다고 자동으로 새 역할을 시작하지 않습니다.

## 보고서 수정과 문제 해결

현재 역할의 보고서에서 **보고서 원문 편집**을 열어 내용을 검토·수정할 수 있습니다.
JSON 형식을 유지하고 `runId`, `stageId`, `attempt`는 바꾸지 마세요.
저장하지 않은 편집 내용이 있을 때 다른 기록으로 이동하려면 먼저 저장하거나 취소해야 합니다.

| 표시 또는 상황 | 할 일 |
|---|---|
| 설치 필요 | 해당 CLI 설치 후 AI 팀을 다시 열어 설치 상태 확인 |
| OpenCode 모델 목록에 없음 | Go 연결과 프로젝트 설정을 확인하고 모델 목록에서 정확한 전체 ID를 선택한 뒤 새 작업 생성 |
| OpenCode 시작 옵션 확인 실패 | CLI의 지원 옵션과 실행 설정을 확인하거나 OpenCode 업데이트 |
| 입력이나 확인 대기 | **작업 탭에서 보기**로 해당 역할의 로그인·권한 질문 확인; 처리한 뒤 **보고서 다시 읽기**로 상태 확인 |
| Claude가 홈 폴더의 신뢰를 실행할 때마다 질문 | **팀 관리**에 표시된 프로젝트 경로와 터미널의 `Accessing workspace`를 비교; 홈 폴더에 저장된 작업은 종료 상태를 확인한 뒤 실제 프로젝트 폴더로 새 작업 생성 |
| Windows에서 선택한 프로젝트와 실제 시작 폴더가 다름 | 0.1.24 이상으로 업데이트; 기존 터미널의 위치는 자동 변경되지 않으므로 해당 실행 상태를 확인한 뒤 다시 시작 |
| 0.1.22에서 `tab.layout changed`로 작업 탭이 열리지 않음 | 0.1.23 이상으로 업데이트하고 기존 작업에서 **실시간 작업 탭 열기** 또는 **작업 탭에서 보기**; 현재 AI를 새로 시작하지 않음 |
| 0.1.22에서 `cx is no longer valid` 표시 | 0.1.23 이상으로 업데이트하고 기존 작업을 다시 열어 실행 상태 확인; 오류 전에 시작한 AI는 같은 작업 탭에서 확인 |
| 보고서가 없음 | 터미널에서 작업 결과와 지정된 JSON 보고서 작성 여부 확인 후 **보고서 다시 읽기** |
| 보고서 형식 또는 식별자 오류 | 해당 역할에게 지정된 경로·형식·시도 번호로 보고서를 다시 작성하도록 요청 |
| 보고서에 `blocked` | 원인을 해결하고 담당자의 보고서를 갱신한 뒤 진행 |
| 실행 여부 확인 대기 | 늦게 생성된 터미널을 중복 실행하지 않도록 상태 확인을 기다림 |
| 이전 버전의 실행 결과·작업 정보 불일치 | 0.1.21 이상으로 업데이트하고 기존 작업을 열어 **보고서 다시 읽기**로 실행 상태 재확인; 새 작업을 중복 시작하지 않음 |
| 이전 버전에서 보고서가 있는데 다음 역할로 넘어가지 않음 | 0.1.21 이상에서 기존 작업 상태를 다시 읽고 완료·승인 대기 여부 확인; 자동 진행을 원하면 **보고서가 준비되면 다음 역할 자동 실행**을 다시 선택 |
| 중지·실행 오류 | 기존 터미널 상태를 확인한 뒤 **이 단계 다시 실행**; 이전 AI가 작업 중이면 재시도 거부 |

통신 오류로 실행 응답을 받지 못한 상태에서는 동일 역할을 무조건 다시 실행하지 않습니다.
기존 실행의 식별 라벨로 터미널을 찾아 연결하며, 발견되지 않았다는 이유만으로
실행되지 않았다고 단정하지 않습니다. 실행 엔진 상태와 해당 터미널을 먼저 확인하세요.

## 기록과 파일

작업별 파일은 선택한 프로젝트 아래에 생성됩니다.

```text
.ai-hub/team/<작업 ID>/
  plan-1.md          계획 역할의 요청과 보고서 작성 형식
  plan-1.json        해당 시도의 구조화된 보고서
  implement-1.md     다음 역할의 요청과 이전 인수인계
  implement-1.json
  handoff.md         기록 내보내기로 생성한 문서
  run.json           기록 보관으로 생성한 작업 기록
```

재시도하면 시도 번호가 바뀌며 이전 시도의 파일을 덮어쓰지 않습니다.
Git 저장소에서는 `.ai-hub/team/`을 로컬 `info/exclude`에 추가합니다.
이 설정은 그 저장소의 로컬 제외 규칙이며 추적 중인 `.gitignore`를 수정하지 않습니다.
이미 Git에서 추적 중인 파일을 추적 해제하지는 않습니다.

역할 설정과 최근 작업은 AI Hub 설정 폴더의 `shared.json`에 저장됩니다.
최근 작업은 최대 20개이며, 한도를 넘으면 기존 기록을 지우는 대신 새 작업을 만들지 않습니다.
**기록 내보내기**는 보고서를 `handoff.md`로 저장합니다.
완료하거나 아직 시작하지 않은 작업의 **기록 보관**은 `run.json`을 저장하고 최근 목록에서 제거합니다.
프로젝트의 보고서 파일과 터미널은 이 동작으로 삭제하지 않습니다.

## 이번 버전의 범위

- 현재 컴퓨터의 로컬 프로젝트에서 역할을 순차 실행합니다. AI 팀의 SSH 원격 실행은 지원하지 않습니다.
- 여러 역할이 같은 프로젝트 폴더를 사용합니다. 역할마다 별도 Git worktree를 만들지는 않습니다.
- 인수인계 보고서로 맥락을 전달합니다. 도구 사이에 계정이나 전체 대화 세션을 공유하지 않습니다.
- 앱의 팀 화면이 열려 있는 동안 상태를 확인합니다. 화면을 닫아도 실행 중인 터미널은 계속될 수 있으며,
  새 역할의 자동 시작은 중단됩니다.
- 모델 이용료·구독·로그인은 각 도구의 계정과 설정을 따릅니다.

## 개발 및 검증

순서·상태·보고서 모델은 `defaults/mods/team/model.js`, 실행과 저장은 `runtime.js`,
네이티브 화면은 `main.js`에 있습니다. 모델과 런타임 검사는 다음 명령으로 실행합니다.

```sh
node --test scripts/test_team.mjs scripts/test_team_runtime.mjs scripts/test_team_workspace.mjs
```

CI는 Linux·Windows·macOS에서 위 검사와 기존 Rust 검사를 수행합니다.
Linux에서는 `scripts/test-team-ui.py`로 실제 앱의 모드 검사기를 실행해 상태별 화면 요소를
검사하고 진단 자료를 남깁니다. 이 검사는 실제 유료 AI 계정의 호출이나 Windows 데스크톱의
입력·화면 배치 검사를 대체하지 않습니다. 실행별 결과는 GitHub Actions에서 확인하세요.

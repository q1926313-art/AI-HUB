# AI 팀 사용 안내

AI Hub의 **AI 팀**은 하나의 목표를 계획·구현·검토·검증으로 나누어 각 역할의 AI를
순서대로 실행하는 기능입니다. 앞 역할의 보고서와 원래 목표를 다음 역할에 전달합니다.
이 문서는 `0.1.17-aihub.2`의 동작을 설명합니다.

## 시작하기

1. 사용할 CLI를 PC에 설치하고 각 도구의 로그인을 마칩니다.
   기본 구성에는 Claude Code, Codex, Gemini CLI가 사용됩니다.
2. AI Hub의 사이드바 하단 **AI 팀**을 누릅니다. 명령 팔레트에서 **AI 팀**을 검색하거나
   `herdr-app do mod.open --name team`을 실행해도 됩니다.
3. **역할 설정**에서 담당 도구의 설치 상태를 확인합니다. 설치된 다른 도구를 선택하거나
   필요 없는 역할을 끄고, 프로젝트에 맞는 지침을 저장할 수 있습니다.
4. **새 작업**에서 작업 이름, 목표와 완료 조건, 프로젝트 폴더의 전체 경로를 입력합니다.
5. **AI 팀 시작**을 누릅니다. 처음 사용하는 도구의 로그인·신뢰·권한 질문은 해당 역할의
   **터미널 열기**에서 확인하고 처리합니다.
6. 보고서가 도착하면 변경사항, 검사 결과, 남은 문제를 읽고
   **인수인계 확인 · 다음 단계 실행**을 누릅니다. 마지막 역할에서는 팀 작업을 마칩니다.

### 기본 역할

| 순서 | 역할 | 담당 도구 | 기본 요청 |
|---|---|---|---|
| 1 | 계획 | Claude Code | 기존 규칙과 코드를 읽고 범위, 구현 순서, 확인 기준 정리 |
| 2 | 구현 | Codex | 요청 범위의 코드 구현, 기존 변경 보존, 필요한 검사 실행 |
| 3 | 검토 | Claude Code | 변경 내용, 누락, 회귀 가능성을 읽기 전용으로 검토 |
| 4 | 검증 | Gemini CLI | 허용된 검사를 실행하고 직접 확인한 결과와 미실행 검사 구분 |

담당 도구를 같은 것으로 통일해도 각 역할은 별도 터미널에서 시작합니다.
설정 변경은 **새로 만드는 작업**에 적용됩니다. 진행 중인 작업에는 시작 당시 역할과 지침이 남습니다.

계획·검토·검증의 읽기 전용 지침은 AI에게 주는 요청입니다. 운영체제의 파일 쓰기 권한을
제한하는 기능은 아닙니다. AI Hub는 도구의 기존 실행 인자를 유지하고 권한 확인을 일괄 생략하는
옵션을 추가하지 않습니다. 각 CLI가 지원하는 권한 설정은 해당 도구에서 관리하세요.

## 인수인계와 자동 진행

기본값은 **수동 인수인계**입니다. 보고서에는 작업 요약, 변경사항, 테스트 명령과 결과,
남은 문제, 다음 역할에 전달할 내용이 포함됩니다. 화면의 **통과 보고**는 AI가 제출한 결과이며,
AI Hub가 그 명령을 별도로 재실행해 확인했다는 뜻은 아닙니다.

자동 진행을 선택하면 다음 조건을 확인합니다.

- 현재 작업·역할·시도 번호와 일치하는 유효한 완료 보고서가 있습니다.
- 실행 엔진에서 작업 후 대기·완료 전환을 관측했거나, 프로세스가 종료 코드 0으로 끝났습니다.
  시작 직후의 대기 상태만으로는 진행하지 않습니다.
- 보고서에 실패한 검사나 남은 문제가 없습니다. `not_run`은 실행하지 않은 검사로 표시되며,
  그 자체를 실패로 처리하지는 않습니다.

로그인·권한 확인 등 입력 대기, 오류, 실행 중단, 실패한 검사나 남은 문제를 확인하면 자동 진행을
멈춥니다. 보고서가 없거나 쓰는 중이어서 유효하지 않으면 다음 역할을 시작하지 않습니다.
보고서가 있어도 실행 중인 AI를 건너뛰어 다음 역할을 실행하지 않습니다.

**자동 진행 멈추기**는 이후 역할의 자동 실행을 멈추며 현재 AI의 작업은 계속됩니다.
현재 작업까지 멈추려면 **현재 AI 중지 요청**을 사용하고 터미널 상태를 확인하세요.
팀 화면을 닫거나 다른 화면으로 이동하거나 보고서를 편집하면 자동 진행은 해제됩니다.
앱이나 기록을 다시 열었다고 자동으로 새 역할을 시작하지 않습니다.

## 보고서 수정과 문제 해결

현재 역할의 보고서에서 **보고서 원문 편집**을 열어 내용을 검토·수정할 수 있습니다.
JSON 형식을 유지하고 `runId`, `stageId`, `attempt`는 바꾸지 마세요.
저장하지 않은 편집 내용이 있을 때 다른 기록으로 이동하려면 먼저 저장하거나 취소해야 합니다.

| 표시 또는 상황 | 할 일 |
|---|---|
| 설치 필요 | 해당 CLI 설치 후 AI 팀을 다시 열어 설치 상태 확인 |
| 입력이나 확인 대기 | 해당 역할의 터미널을 열어 로그인·권한 질문 확인 |
| 보고서가 없음 | 터미널에서 작업 결과와 지정된 JSON 보고서 작성 여부 확인 후 **보고서 다시 읽기** |
| 보고서 형식 또는 식별자 오류 | 해당 역할에게 지정된 경로·형식·시도 번호로 보고서를 다시 작성하도록 요청 |
| 보고서에 `blocked` | 원인을 해결하고 담당자의 보고서를 갱신한 뒤 진행 |
| 실행 여부 확인 대기 | 늦게 생성된 터미널을 중복 실행하지 않도록 상태 확인을 기다림 |
| 중지·실행 오류 | 기존 터미널 상태를 확인한 뒤 **이 단계 다시 실행**; 이전 AI가 작업 중이면 재시도 거부 |

통신 오류로 실행 응답을 받지 못한 상태에서는 동일 역할을 무조건 다시 실행하지 않습니다.
기존 실행의 식별 라벨로 터미널을 찾아 연결하며, 발견되지 않았다는 이유만으로
실행되지 않았다고 단정하지 않습니다. 실행 엔진 상태와 해당 터미널을 먼저 확인하세요.

## 기록과 파일

작업별 파일은 선택한 프로젝트 아래에 생성됩니다.

```text
.ai-hub/team/<작업 ID>/
  plan-1.md          계획 역할의 요청과 보고서 작성 형식
  plan-1.json        해당 시도의 구조화된 보고서
  implement-1.md     다음 역할의 요청과 이전 인수인계
  implement-1.json
  handoff.md         기록 내보내기로 생성한 문서
  run.json           기록 보관으로 생성한 작업 기록
```

재시도하면 시도 번호가 바뀌며 이전 시도의 파일을 덮어쓰지 않습니다.
Git 저장소에서는 `.ai-hub/team/`을 로컬 `info/exclude`에 추가합니다.
이 설정은 그 저장소의 로컬 제외 규칙이며 추적 중인 `.gitignore`를 수정하지 않습니다.
이미 Git에서 추적 중인 파일을 추적 해제하지는 않습니다.

역할 설정과 최근 작업은 AI Hub 설정 폴더의 `shared.json`에 저장됩니다.
최근 작업은 최대 20개이며, 한도를 넘으면 기존 기록을 지우는 대신 새 작업을 만들지 않습니다.
**기록 내보내기**는 보고서를 `handoff.md`로 저장합니다.
완료하거나 아직 시작하지 않은 작업의 **기록 보관**은 `run.json`을 저장하고 최근 목록에서 제거합니다.
프로젝트의 보고서 파일과 터미널은 이 동작으로 삭제하지 않습니다.

## 이번 버전의 범위

- 현재 컴퓨터의 로컬 프로젝트에서 역할을 순차 실행합니다. AI 팀의 SSH 원격 실행은 지원하지 않습니다.
- 여러 역할이 같은 프로젝트 폴더를 사용합니다. 역할마다 별도 Git worktree를 만들지는 않습니다.
- 인수인계 보고서로 맥락을 전달합니다. 도구 사이에 계정이나 전체 대화 세션을 공유하지 않습니다.
- 앱의 팀 화면이 열려 있는 동안 상태를 확인합니다. 화면을 닫아도 실행 중인 터미널은 계속될 수 있으며,
  새 역할의 자동 시작은 중단됩니다.
- 모델 이용료·구독·로그인은 각 도구의 계정과 설정을 따릅니다.

## 개발 및 검증

순서·상태·보고서 모델은 `defaults/mods/team/model.js`, 실행과 저장은 `runtime.js`,
네이티브 화면은 `main.js`에 있습니다. 모델과 런타임 검사는 다음 명령으로 실행합니다.

```sh
node --test scripts/test_team.mjs scripts/test_team_runtime.mjs
```

CI는 Linux·Windows·macOS에서 위 검사와 기존 Rust 검사를 수행합니다.
Linux에서는 `scripts/test-team-ui.py`로 실제 앱의 모드 검사기를 실행해 상태별 화면 요소를
검사하고 진단 자료를 남깁니다. 이 검사는 실제 유료 AI 계정의 호출이나 Windows 데스크톱의
입력·화면 배치 검사를 대체하지 않습니다. 실행별 결과는 GitHub Actions에서 확인하세요.

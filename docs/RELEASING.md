# AI Hub 배포 관리

첫 자동 정식 배포 버전은 `0.1.19`입니다. 새 숫자 버전을 담은 `main` 커밋이
플랫폼 검사와 Windows 패키징을 통과하면 GitHub Releases에 공개합니다.
현재 정식 설치·자동 업데이트 배포 대상은 Windows x64입니다.

## 새 버전 준비

1. `Cargo.toml`의 `[package]` 버전과 `Cargo.lock`의 `herdr-app` 버전만 함께 올립니다.
   이미 공개한 최신 버전보다 큰 **숫자 `x.y.z`**를 사용합니다. 예: `0.1.19` → `0.1.20`.
   `Cargo.toml`의 수정 고지 주석은 버전과 같은 줄에 유지하고, 의존성 버전은 건드리지 않습니다.
2. `CHANGELOG.md` 맨 위에 `## [버전] - YYYY-MM-DD`와 사용자 관점의 변경 사항을 추가합니다.
   필요한 `### New` / `### Fixed` 항목을 쓰고, 한 번 열리는 업데이트 안내가 필요하면
   `<!-- spotlight windows -->`를 넣습니다.
3. 변경을 `main`에 반영합니다. 배포 흐름이 해당 커밋에 `v<버전>` 태그를 생성하므로
   정상적인 새 버전 배포를 위해 태그를 먼저 만들 필요는 없습니다.
4. [Actions](https://github.com/q1926313-art/AI-HUB/actions)에서 같은 커밋의 검사와 배포 결과를 확인한 뒤,
   [Releases](https://github.com/q1926313-art/AI-HUB/releases)에서 공개된 버전과 파일을 확인합니다.

이전 앱의 버전 비교는 프리릴리스 접미사를 문자열로 비교합니다. `-aihub.10` 같은 번호를
이어 쓰면 정렬 순서가 뒤집힐 수 있어, 첫 정식 버전은 숫자 본체를 올린 `0.1.19`로 시작합니다.
이후 자동 배포에서는 프리릴리스 접미사나 빌드 메타데이터 없는 숫자 버전만 사용합니다.

## 공개 조건과 실패 처리

[CI](../.github/workflows/ci.yml)는 Linux·macOS·Windows 검사를 수행하고,
[Windows 배포 흐름](../.github/workflows/release.yml)은 설치 파일과 업데이트 목록을 만듭니다.
공개 단계는 **배포할 정확한 커밋의 성공한 CI**를 확인합니다. 다른 커밋의 성공으로 대체하지 않습니다.
검사나 패키징에 실패하면 정식 버전을 공개하지 않습니다.

파일은 먼저 초안 릴리스에 올립니다. 필요한 파일 목록, SHA-256, 업데이트 목록의 버전과 주소,
태그가 가리키는 커밋을 검사하고, 공개 직전 CI와 `main`의 커밋을 다시 확인합니다.
검증을 마친 초안만 정식 릴리스와 최신 버전으로 전환합니다.

- 공개한 버전의 태그와 파일은 덮어쓰지 않습니다. 동일 버전·동일 커밋을 재실행하면 기존 배포를 유지합니다.
- 같은 버전의 태그가 다른 커밋을 가리키면 배포를 거부합니다. 버전을 올려 새 배포를 만드세요.
- 같은 커밋에서 일시적인 업로드 실패가 발생했다면 배포 작업을 재실행할 수 있습니다.
  미완성 초안은 앱의 정식 업데이트 대상이 아닙니다.
- 수정 커밋을 추가했거나 기존 태그가 다른 커밋에 있다면 새 버전으로 진행합니다.
  최신 공개 버전보다 낮거나 같은 버전을 새 최신 버전으로 올리는 것도 거부합니다.

실제 확인 로직은 [게시 스크립트](../scripts/publish_release.py)와
[패키지 목록 생성 스크립트](../scripts/prepare_release.py)에 있습니다.

## 사용자에게 반영되는 방식

새 설치에는 [최신 Windows ZIP](https://github.com/q1926313-art/AI-HUB/releases/latest/download/AI-Hub-windows-x86_64.zip)을
안내합니다. ZIP 전체를 푼 다음 `herdr-app/Install.cmd`를 실행합니다.
PowerShell 설치가 필요하면 정식 배포에 포함된
[`install.ps1`](https://github.com/q1926313-art/AI-HUB/releases/latest/download/install.ps1)을 사용합니다.

설치된 앱은 시작 약 10초 후 업데이트를 확인하고, 확인에 성공하면 1시간 뒤,
실패하면 30분 뒤 다시 확인합니다. 즉시 확인하려면 **Settings → Updates → Check now**,
다운로드가 준비되면 **Restart to update**를 사용합니다.
일반 소스 개발 빌드는 기본적으로 앱 자동 업데이트를 하지 않습니다.
`herdr-core`의 배포 주소와 업데이트는 별도로 유지합니다.

재설치는 앱 설치 폴더를 교체하며, 같은 앱 홈의 개인 설정·사용자 정의 역할·기존 팀 작업 기록을 유지합니다.
프로젝트 파일과 `.ai-hub/team/`의 보고서는 교체하지 않습니다.
초기 기본값 그대로인 이전 팀 프로필만 새 기본 구성으로 옮기며, 사용자 정의 프로필과
기존 작업에 저장된 담당·모델·지침은 바꾸지 않습니다. 역할 설정 변경은 새 작업에 적용됩니다.
